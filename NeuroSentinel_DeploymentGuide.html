🚀 Free Deployment Solution

✅ The Fix: Move Backend from Render → Hugging Face Spaces (Docker) Hugging Face Spaces free CPU tier gives you 16 GB RAM — 32× more than Render's 512 MB free tier. Your model needs ~300–400 MB for inference. This is the only zero-cost platform with enough RAM to run PyTorch reliably. Frontend stays on Vercel (already working fine).

Backend Migration

Step-by-Step: Render → HF Spaces

1
Create a Dockerfile in neurosentinel-backend/
HF Docker Spaces run any Dockerfile you give them. Port must be 7860.
# neurosentinel-backend/Dockerfile
FROM python:3.11-slim

# System dependencies for MNE (needs some libs)
RUN apt-get update && apt-get install -y \
    libgomp1 \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY pyproject.toml .
RUN pip install --no-cache-dir -e .

COPY . .

# HF Spaces requires port 7860
EXPOSE 7860

CMD ["uvicorn", "app.main:app", \
     "--host", "0.0.0.0", \
     "--port", "7860", \
     "--workers", "1"]
2
Add README.md with HF Space config header
HF reads YAML front-matter at the top of README.md to configure the Space.
---
title: NeuroSentinel Backend
emoji: 🧠
colorFrom: blue
colorTo: cyan
sdk: docker
pinned: false
app_port: 7860
---

# NeuroSentinel AI — FastAPI Backend
Production EEG seizure detection API.
Model: MultiRepEEGModel V4 (409K params, 99.55% accuracy)
3
Create the Space on Hugging Face
Go to huggingface.co/new-space → Name: neurosentinel-backend → SDK: Docker → Visibility: Public → Create Space.
4
Add your environment variables as Secrets
In the Space → Settings → Variables and Secrets tab. Add each as a Secret (encrypted):
SUPABASE_URL          = https://xxxx.supabase.co
SUPABASE_SERVICE_KEY  = eyJ...
GEMINI_API_KEY        = AIza...
GROQ_API_KEY          = gsk_...
HUGGINGFACE_API_KEY   = hf_...
APP_URL               = https://neurosentinel.vercel.app
5
Push your backend code to the Space repo
HF Spaces are git repos. Add the HF remote and push.
# From your seizure/ git root
cd neurosentinel-backend

git init   # (or use your existing git)
git remote add hf https://huggingface.co/spaces/YOUR_USERNAME/neurosentinel-backend

git add .
git commit -m "deploy: initial HF Spaces deployment"
git push hf main
HF will auto-detect the Dockerfile and start building. Watch the build logs in the Space UI.
6
Update NEUROSENTINEL_BACKEND_URL in Vercel
Your new backend URL will be:
https://YOUR_USERNAME-neurosentinel-backend.hf.space

Go to Vercel → Project → Settings → Environment Variables → update NEUROSENTINEL_BACKEND_URL to the new HF URL. Redeploy.
7
Test the health endpoint
Once deployed, verify everything is up:
curl https://YOUR_USERNAME-neurosentinel-backend.hf.space/health

# Expected response:
{
  "status": "healthy",
  "model_loaded": false,  ← fine, loads on first request
  "memory_mb": ~800        ← PLENTY of headroom
}
💡 Keeping the Space Awake (Optional) Use a free uptime monitor like UptimeRobot (uptimerobot.com) to ping /health every 30 minutes. This prevents the Space from sleeping. Free plan allows 50 monitors.

Inference Pipeline (What runs on every EDF upload)

EDF upload → Supabase Storage (eeg-uploads bucket)
    ↓
Render/HF backend receives file_url
    ↓
Stage 1: preprocess_any_edf()
  • Load via MNE (lazy)
  • Drop non-EEG channels
  • Resample to 256 Hz
  • Detect montage (bipolar vs referential)
  • Universal adapter → 22-ch bipolar
  • Notch filter (50/60Hz) + Bandpass (0.5–40Hz)
  • IQR-based robust normalization
  • Window into 4s × 22ch = 1024 samples
    ↓
Stage 2: definitive_inference()
  • Chunked: 50 windows/chunk, batch size 4
  • gc.collect() after every chunk
  • Output: per-second seizure probability array
    ↓
Stage 3: Domain shift detection
  • prob_median < 0.15  → NONE  → standard thresholds
  • prob_median 0.15–0.4 → LOW  → moderate thresholds
  • prob_median 0.4–0.7  → MOD  → strict thresholds
  • prob_median ≥ 0.7    → HIGH → fixed absolute 0.90
    ↓
Stage 4: Post-processing (5-stage filter)
  1. Smooth (moving avg, window=7)
  2. Hysteresis (P99 start, 0.7×high end)
  3. Duration filter (min 15s)
  4. Merge (gap < 5s)
  5. Mean filter (min_mean ≥ 0.90, sustained ≥ 5s)
    ↓
Stage 5: Explainability
  • Channel importance (occlusion)
  • Brain heatmap (10-20 regions)
    ↓
Stage 6: Report generation
  • Severity score (0–10), risk level, SE flag
  • Band powers per event, quality assessment
  • Role-aware PDF (clinician / researcher / patient)
  • Upload PDF → Supabase report-pdfs bucket
    ↓
Frontend polls every 4s → auto-redirect to report page

Critical Lessons (Never Forget)

#LessonWhy It Matters
1Training ↔ inference preprocessing must be byte-identicalV3→V4 fix: preprocessing mismatch was the root cause of prod degradation
2Never use BNA (Batch Norm Adaptation)Catastrophic — raised CHB-MIT prob_mean from 0.01 to 0.78
3Never use TTN (Test-Time Normalization)Signal-level stats don't reveal domain shift — model output does
4T8-P8 augmentation is criticalALL test patients are missing channel 14 — train without it and test drops
5Domain shift from output probs, not signal statsSiena signal looks "low noise" but model outputs 0.38–0.81 background
6HIGH domain shift → fixed absolute threshold (0.90), not percentileSeizure spikes pull P99 to 0.95+, making percentile detection unreliable
7No artifact rejection at inferenceClinical completeness — every window needed for onset/offset precision
8IQR normalization, not z-scoreSeizure spikes are outliers; z-score gets corrupted by them
9Lead with Macro F1 + PR-AUC, not accuracyAccuracy is inflated by 16:1 class imbalance — misleads reviewers
10Chunked inference — never materialize all windows at once50 windows × batch 4 keeps peak RAM under 400 MB — safe on any free tier
